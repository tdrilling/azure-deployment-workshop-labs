Azure Deployment Workshop

Lab-Repository

Neun praktische Labs, eine Leitanwendung: WordPress (Apache/PHP/MySQL) wandert über vier Kurstage vom manuellen VM-Deployment bis zum containerisierten Betrieb — jede Stufe baut auf der vorherigen auf.

📦 9 Labs 🗓️ 4 Kurstage 🔗 GitHub-Repository
TAG 1

VM-basiertes Deployment

Von der manuellen Installation zur automatisierten VM — Linux und Windows.

Lab 01 Manuelle LAMP-Installation auf einer Azure-VM fertig

Azure-VM anlegen, Apache/PHP/MySQL/WordPress vollständig manuell installieren — Referenzpunkt für alle folgenden, zunehmend automatisierten Stufen.

⏱ 45–60 Min.🔑 SSH-Schlüsselpaar
Lab 02 LAMP + WordPress automatisiert per Cloud-Init fertig

Dieselbe Zielarchitektur wie Lab 1, diesmal vollständig automatisiert beim VM-Deployment selbst — kein manueller SSH-Schritt mehr nötig.

⏱ 20–25 Min.📄 cloud-init.yaml
Lab 03 WordPress unter Windows: VM-Erweiterungen, VM-Anwendungen und DSC fertig

Dieselbe Zielarchitektur unter Windows/IIS — Vehikel, um drei verwandte Automatisierungskonzepte einzuordnen: VM-Erweiterungen, VM-Anwendungen und Desired State Configuration.

⏱ 30–40 Min.🪟 Windows-Verwaltungsumgebung
TAG 2

Infrastructure as Code

Dieselbe Architektur deklarativ — erst mit Bicep, dann zum Vergleich mit Terraform.

Lab 04 WordPress deklarativ mit Bicep fertig

Dieselbe Zielarchitektur wie Lab 1/2, diesmal vollständig deklarativ statt imperativ — ab hier durchgängiges IaC-Werkzeug für den Rest des Kurses.

⏱ 30–40 Min.🧱 Bicep-CLI
Lab 05 WordPress deklarativ mit Terraform (einmalige Demonstration) fertig

Dieselbe Zielarchitektur wie Lab 4, diesmal mit Terraform — stellt den State-Datei-basierten Ansatz dem State-losen Bicep-Modell gegenüber. Kurs bleibt danach bei Bicep/ARM.

⏱ 30–40 Min.🌍 Terraform-CLI
TAG 3

App Services

Der Wechsel von IaaS zu PaaS — manuell, deklarativ, und mit echter CI/CD-Pipeline.

Lab 06 Manuelles PHP-Deployment auf App Service fertig

WordPress läuft erstmals auf Azure App Service (PaaS) statt einer selbst verwalteten VM, angebunden an einen echten Azure Database for MySQL Flexible Server.

⏱ 45–60 Min.
Lab 07 Deklaratives App-Service-Deployment (Bicep) fertig

Dieselbe Zielarchitektur wie Lab 6, diesmal deklarativ mit Bicep — keine eigene VM, keine NIC, kein VNet: je höher die Abstraktionsstufe, desto weniger Infrastruktur-Boilerplate.

⏱ 25–30 Min.🧱 Bicep-CLI
Lab 08 CI/CD mit GitHub Actions: Build → Deploy in Slot → Swap fertig

Eine echte, lauffähige GitHub-Actions-Pipeline für die App-Service-Umgebung aus Lab 7: Build → Deploy in den Staging-Slot → Swap in Production.

⏱ 20–25 Min.⚙️ setzt Lab 7 voraus
TAG 4

Container & Kursabschluss

Die dritte Hosting-Stufe der Workshop-Reise: Portabilität statt Plattform-Bindung.

Lab 09 Container-Deployment (Azure Container Instances) fertig

Dieselbe Zielanwendung als portables Container-Image, lokal gebaut und getestet, über Azure Container Registry nach Azure Container Instances deployt.

⏱ 30–35 Min.🐳 Docker Desktop

Voraussetzungen

  • Eine Azure-Subscription mit Berechtigung, Ressourcengruppen und die jeweils genannten Ressourcentypen anzulegen.
  • Azure CLI (az) und/oder Azure PowerShell (Az-Module), abhängig vom Lab.
  • Für die deklarativen Labs: Bicep-CLI (in aktueller Azure CLI enthalten) bzw. Terraform.
  • Für Lab 1/2: ein SSH-Schlüsselpaar (öffentlich/privat), siehe jeweilige Anleitung.
  • Für Lab 3: eine Windows-Verwaltungsumgebung mit PowerShell 5.1+ (DSC).
  • Für Lab 9: Docker Desktop (oder eine gleichwertige lokale Docker-Umgebung).

Repository-Struktur

  • Instructions/ — eine Markdown-Anleitung pro Lab, nummeriert nach Kursreihenfolge.
  • Allfiles/ — die zugehörigen Skripte/Templates, in gleichnamigen Unterordnern.
  • Allfiles/reference/ — zusätzliche, funktionsfähige Vorlagen zum Nacharbeiten (z. B. das ARM-Äquivalent zum Bicep-Lab).
Sicherheitshinweis: Einige Skripte enthalten aus didaktischen Gründen Platzhalter-Kennwörter im Klartext (markiert mit <CHANGE_ME>) — ausschließlich für den Lab-Kontext akzeptabel. In produktiven Deployments gehören Geheimnisse in Azure Key Vault bzw. werden zur Laufzeit injiziert (siehe Tag 3).
